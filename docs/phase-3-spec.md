# Phase 3 Spec — 真实价值流动 + 网络打开

> 历史文档：黑客松时期编写，其中的 Cobo 集成已于 2026-09 移除；现行结算方案见 README「技术架构」。

> **精度：形状，非定稿。** 下面的单元都标了「暂定」——它们会在 **Phase 2 落地后**定稿，因为 Phase 2 的鉴权模型和多方分账的最终形状会直接决定这里怎么拆。现在先给一个可理解、可讨论的骨架，别当成承诺的单元。

---

## 命题

让「价值」从账面变成**真实流动**（结算层：`accrued → settled`），并把网络从「内部 9 个 Agent」打开成「**外部可参与的市场**」。

## 前置（被 Phase 2 挡着，为什么）

- **真实结算**需要 → 结算幂等（否则重复打真钱）+ 真实鉴权（否则给未验证身份打钱）。
- **市场**需要 → 真实鉴权（谁注册 / 谁收钱）+ 多方分账（多个外部贡献者）。

两块都坐在 Phase 2 三条红线之上。红线没收完，这一层立不住。

---

## A 块 — 真实机器支付（结算层）

### U1（暂定）— 结算 provider 接口（缝）

把黑客松的 Cobo 适配器**泛化成一个干净、可换的结算 provider 接口**；定义 `accrued → settled` 状态机；结算幂等（每条账本行只结一次、打款与翻 `settled` 原子完成）。

### U2（暂定）— 一个真实 provider 接入

Cobo / x402 之一，测试网 → 主网路径；钱包 / Pact 设置；受限授权（花费上限 + 允许收款方 + 有效期），即「给 agent 一个 Pact，不是私钥」。

### U3（暂定）— 结算生命周期 + 对账 / 审计

`settled` / `failed` / `retry` 状态；audit log；对账（链上金额 == 账本金额）。

---

## B 块 — Agent 市场

### U4（暂定）— 外部身份 + 资产 / Agent 注册

认证的外部创作者注册资产；AgentCard 数据模型。

### U5（暂定）— AgentCard 展示 + 发现

价格、成功率、创作者、reputation；Agent 世界页从「叙事展示」变成**真实市场**。

### U6（暂定）— reputation 系统

成功率、平均完成时间、用户评分，喂给发现与定价。

---

## 顺序说明

A、B 大体可并行，但都在 Phase 2 之后。具体顺序、是否合并 / 拆分单元，**等 Phase 2 收口再定**。

## 收口判据（方向性）

一笔真实（哪怕测试网）的「任务 → 多方贡献者各自收到 USDC」端到端跑通；外部 agent 能注册、被调用、被记账、被结算。

## 已知会往 Phase 4 推的

- 一次任务用**多个资产**（多 asset）。
- reputation 真正参与撮合 / 定价的**经济效应**。
